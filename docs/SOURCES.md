# Research sources and representative patterns

This standard synthesizes official guidance and representative mature/fast-growing open-source projects. It does not claim every popular project uses every file.

## Primary guidance

- GitHub community health: https://docs.github.com/en/communities/setting-up-your-project-for-healthy-contributions
- README guidance: https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes
- Supply-chain security: https://docs.github.com/en/code-security/concepts/supply-chain-security
- Actions secure use: https://docs.github.com/en/actions/reference/security/secure-use
- Artifact attestations: https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations
- OpenSSF Scorecard: https://github.com/ossf/scorecard
- OpenSSF OSPS Baseline 2026: https://baseline.openssf.org/versions/2026-02-19.html
- OpenSSF Best Practices: https://best.openssf.org/
- Semantic Versioning: https://semver.org/
- Keep a Changelog: https://keepachangelog.com/en/2.0.0/
- Conventional Commits: https://www.conventionalcommits.org/en/v1.0.0/
- Citation File Format: https://citation-file-format.github.io/
- REUSE/SPDX: https://reuse.software/

## Representative repository patterns

Kubernetes informed concise purpose, development/support/governance/roadmap links and high-signal badges. uv informed value proposition, evidence-backed benchmarks, platform/version policy, installation alternatives, contribution, and licensing clarity. FastAPI informed recognizable identity, focused tagline, docs entry, examples, package compatibility, ecosystem positioning, and sponsor separation. Rust, VS Code, Home Assistant, Django, React/Next.js, and curl informed governance, ownership, compatibility, support, and release categories.

Patterns were normalized rather than copied wholesale. Large-project ceremony is optional unless it solves a real project risk.
