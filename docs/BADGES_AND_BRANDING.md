# Badges and branding

## High-signal badge order

1. CI/test status.
2. Security scan or OpenSSF Scorecard.
3. Latest stable release.
4. Supported runtime/platforms.
5. License.
6. Optional coverage, docs, package, downloads, or community links.

Every badge must link to evidence. Remove stale badges. Badge count is not a quality score and a green badge may mean only that one workflow ran.

Provide meaningful alt text and do not encode status only by color.

A mature identity may add a capitalization rule, SVG/PNG logo variants, social preview, short tagline, trademark guidance, and attribution rules. Do not imply a foundation, certification, or affiliation that does not exist.

Register and complete OpenSSF Best Practices before adding its generated badge; never use a placeholder passing badge.
