# Governance

Repo Standard uses a maintainer-led model designed for a small project while preserving transparent decisions and a path to shared stewardship.

## Roles

Contributors submit changes. Reviewers approve within their areas. Maintainers triage, merge, release, handle security reports, and enforce policies. The project owner appoints maintainers, resolves deadlocks, and controls repository access.

## Decisions

Routine changes use pull-request consensus. Changes to compatibility, policy levels, licensing, governance, security boundaries, or release architecture require an issue or ADR. When consensus is impossible, the project owner documents the alternatives and decides.

## Maintainers

Maintainers are selected after sustained, high-quality contributions, reliable reviews, respectful collaboration, and security awareness. Access may be removed for inactivity, compromised credentials, policy violations, unmanaged conflicts, or conduct violations.

Only explicitly authorized maintainers may access private vulnerability reports or release credentials. Security-sensitive actions should use least privilege and a second reviewer when practical.

## Succession

If the owner is inactive for 90 days and cannot be contacted, active maintainers may document a succession proposal and transfer operational responsibility by consensus, subject to GitHub controls.
